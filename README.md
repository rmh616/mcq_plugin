# mas

一个 Chrome / Edge 扩展（Manifest V3）：自动识别网页上的选择题，调用 OpenAI 兼容接口拿答案，然后高亮 / 自动选中 / 自动提交并翻页。

> **先说清楚**：自动提交模式会替你点下提交按钮。用在计分的考试、测验上属于学术不端。只在练习题、题库自测、或你自己做的页面上用。页面里随时按 `Esc` 可以立刻中断。

---

## 安装

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选中本文件夹 `mcq_plugin`
4. 点工具栏上的图标，填入 API Key，点「测试连接」确认通了

## 用法

点工具栏图标打开设置面板：

| 按钮 | 作用 |
| --- | --- |
| **扫描本页** | 只识别不作答。检测到的选项会蓝色虚线框高亮 4 秒，右下角面板列出题干、选项和识别到的提交按钮。**排查问题先用它。** |
| **开始** | 按当前模式跑起来。进度显示在页面右下角的悬浮面板里。 |
| **停止** | 中断。页面里按 `Esc` 等效。 |
| **重置本页去重** | 清掉「这题做过了」的记录，让同一页可以重跑。 |

三种模式：

- **仅高亮建议** —— 不点击选项，按住 `Ctrl + Alt + P` 查看推荐答案。
- **自动选中，不提交** —— 替你勾选，提交交给你。
- **自动选中并提交 / 翻页** —— 全自动，一路做到底。

首次在设置中填写 API Key 后，题目加载完成即可直接按住 `Ctrl + Alt + P`，无需打开插件或点击「开始」。快捷键启动仅高亮作答，并隐藏页面悬浮窗口；若原有自动作答正在运行，会先停止该流程。首次求解需要等待模型回复，松开后仍会完成求解，但答案保持隐藏。再次按住时直接显示已生成答案，同页新题会重新扫描。快捷键不会选中、填写答案或提交，也不会改动已保存的模式设置。需要查看日志或手动启动原有模式时，从插件点击「扫描本页」或「开始」可恢复悬浮窗口。

`Alt + Shift + W` 是逐项选择快捷键：一页多题时按页面从上到下的顺序，每按一次为一道未完成MCQ选择一个模型建议的正确选项，随后按键继续下一题，不受当前滚动位置或焦点影响。多选题每次勾选一个正确项，正确项选齐后继续下一题。顺序完成前修改已处理题的选择不会倒退；全部选完后再按一次，进入整页核对，按已有模型答案一次修正全部错选、漏选及多勾项，已正确的题目保持不动。再次核对无错误时不修改或重复请求模型；核对不是独立重新验证模型答案的准确性。站点拒绝修正时记录失败并继续其余题目，可在下一次核对中重试。

优先适配Canvas Classic的单选、多选、True/False和原生下拉匹配，兼容其字母标签映射与原生change事件；iframe中的题目需在该frame内接收按键。支持复用已有高亮答案缓存。长按不重复执行；文字题忙碌时忽略额外按键，图片题等待期间最多保留4次独立按键，每次仍只选择一个选项，按页面顺序执行。Canvas下拉匹配每次按键填写一行，也参与末尾整页纠错。仅执行选中，不提交、不翻页、不选择Get Started，也不打开悬浮窗口。跳过只读、识别不完整、数字题及Sage下拉配对题。按Esc、切换窗口或离开页面会取消尚未发生的修改。Canvas New Quizzes尚未做实际页面验证。

多题性能：Canvas按题缓存解析结果，题干/选项/控件或相关显示状态变化时只重扫受影响题目；选中状态直接读取实际控件，不重新解析整页。高亮返回和点击前校验也复用该索引。整页修正不逐题滚动，并分段让出事件循环以响应绘制和Esc。

Sage 的 `Get Started` 入口也会自动点击。手动「开始」或按一次快捷键后，插件先保存续跑状态，再按站点原有表单提交并跳转到题目页；新页面载入后无需重新启动。快捷键通过独立的 `highlight` 会话恢复，只准备高亮，不选中或提交题目，并继续隐藏窗口；新页仍需按住快捷键才显示答案。这里的「不提交」指题目答案，进入测验的 `Get Started` 表单会正常 POST。普通开始保留原作答模式。原生表单导航发生后，旧页面会等待新文档接管，不因等题超时而清除会话。

答案高亮默认隐藏，松开任意一键立即隐藏。窗口失焦、切换标签页或页面刷新也会隐藏；同一标签页的 iframe 同步求解和显示。扫描的蓝色虚线框仍正常显示。数字填空的快捷键仅高亮输入框，不显示或填写数值。

Canvas 已提交的选择题回顾页也支持此快捷键：直接高亮页面 `correct_answer` 标出的已公开答案，无需 API Key 或模型请求。原始选中和禁用状态保持不变；未公开正确答案的只读题不高亮。

Sage 的下拉配对题（`matchingType`）按行识别：每条描述和该行的候选类别作为一个子题求解，忽略 `Select option` 占位项。仅高亮或快捷键模式会在下拉框旁显示「建议：类别」，按住快捷键可见、松开隐藏，不改变选择值。自动选中模式通过每行实际选项值填写并触发 `input/change`；自动提交模式等待全部配对项成功后才提交。各行选项值可以不同，不假设同名类别共用同一个值；描述缺失、值重复或填写校验失败会阻止提交。当前支持此 Sage 原生单选下拉结构，不包含拖拽配对或自定义多选下拉组件。

置信度低于 0.5 的显示橙色框，面板里也会标出来。

## 针对「一页一题 + 提交按钮」的优化

这类流程（Quizlet、Duolingo 式题库、大部分 LMS 的逐题模式）做了专门处理：

- **按钮按位置打分**：题目容器内部 / 正下方 / 距离近的按钮加分；`nav`、`header`、`footer`、`aside`、侧边栏里的按钮降权 6 分。页首那个「Next」链接不会被误点。
- **提交前先校验**：确认选项真的进入选中状态（`checked` / `aria-checked` / `selected` 类名）才提交；第一次点击没生效会换个目标重试一次，还是不行就停下并在面板报错——**绝不交白卷**。
- **等按钮解锁**：很多站点选完答案才把提交按钮从 disabled 放出来，会等它最多 3 秒。
- **两段式流程**：支持 `提交 → 对错反馈页 → 下一题`，一轮内最多连点 4 次按钮。
- **不傻等超时**：反馈页上一旦「DOM 静默 + 刚点的按钮消失 + 出现了另一颗非导航按钮」，立刻推进，不会白等满 `pageTimeout`。真超时了会在面板记一条 ⏱ 提示你调参。
- **等的是「新题目出现」**，不是 DOM 静默猜测 —— 靠题干+选项的 hash 去重，同一题不会重复问模型、重复作答。
- **刷新后自动续跑**：运行状态和已完成题目的 hash 按标签页保存在浏览器会话中。Submit / Next 导致整页刷新后，新页面会自动恢复；如果落在保留原题的对错反馈页，会直接点击 Next，不重复调用模型。按 Esc、点停止或流程正常结束会清掉恢复状态。
- **跨章节活动页推进**：支持 `Next: Knowledge Check → 章节概览 → Knowledge Check 3.4 → 新题` 这类三段流程。会排除 Sage 页面首尾同名但只指向 `#next-page` 的无障碍跳转链接，优先真正的跨页按钮；扫描到带 `next` 类的外层容器时会改点内部真实链接，常规点击被站点吞掉时会用按钮自带地址在当前页继续。
- **章末测验入口**：识别 `Next: Chapter Quiz` 和 `Chapter 7 Quiz`。优先正文入口，正文缺失时才使用侧栏；也检查 `aria-label/title` 中的 Previous/返回方向，避免回到上一节。自动推进不点击 `Do The Activity` 或重做活动入口；找不到正确候选时停止。章节测验的点击兜底与跨页 GET 续跑均保留会话，不会在旧页面超时后丢失运行状态。作答时，本题 Submit/Continue 仍优先于外部章末入口。

## 支持的题目结构

| 类型 | 说明 |
| --- | --- |
| 原生 `radio` / `checkbox` | 按 `name` 分组；checkbox 按最近的公共容器分组并识别为多选 |
| 视觉隐藏的 `radio` | 自动改点对应的 `<label>` |
| ARIA | `[role=radiogroup]` + `[role=radio]`、`[role=listbox]` + `[role=option]` |
| 纯 `div` / `li` 列表 | 靠 `A.` `(B)` `3、` `D：` 这类前缀识别 |

题干靠「父容器文本减去各选项文本」得到，向上最多爬 7 层，遇到含有别的题目选项控件的容器就停 —— 所以不会把整页文字吸进题干，页面上的主题切换之类的 UI 开关也不会被误判成题目。

React / Vue 的受控组件：点击之外还会绕过框架的 setter 直接改 `checked` 再派发 `input`/`change`。iframe 里的题目也能做（`all_frames`），子 frame 的日志会转发到顶层面板。

## 配置项

| 项 | 默认 | 说明 |
| --- | --- | --- |
| Base URL | `https://api.openai.com/v1` | 任何 OpenAI 兼容端点都行（自建代理、中转、网关） |
| 模型 | `gpt-4o-mini` | 自由填写 |
| 每题间隔 | 700ms | 点选动作之间的停顿 |
| 提交前等待 | 1500ms | 选完到点提交之间的停顿 |
| 等下一题超时 | 8000ms | 点了提交后最多等多久。网慢就调大 |
| 最多翻页轮数 | 50 | 防跑飞的硬上限 |
| 并发请求数 | 2 | 一页多题时并发问模型；一页一题时无效 |
| 缓存答案 | 开 | 同一题（hash 相同）不重复花钱。「清空答案缓存」可清 |
| 附加提示词 | 空 | 例如「这是大一微观经济学的练习题，按课本定义作答」 |

API Key 存在 `chrome.storage.local`（不走同步），网络请求只在 service worker 里发，**不会进入页面上下文**，页面脚本读不到。

## 排查

**识别不到题目** —— 先点「扫描本页」。面板里没列出题目，说明选项结构不在支持范围内。打开控制台看：

```bash
__MCQ_DETECTOR__.collect()
```

**点错按钮 / 找不到提交按钮** —— 控制台里看它选中了谁、打了多少分：

```bash
__MCQ_DEBUG__.findAdvanceButton(null)
```

`__MCQ_DEBUG__` 还有 `state`（含 `stats.timeouts`）、`pendingQuestions()`、`advance()`。

**点 Submit / Next 后刷新并停住** —— 新版会自动恢复。页面右下角会显示「页面刷新后已恢复」；若仍未恢复，先确认扩展已在 `chrome://extensions/` 里重新加载。

**刚装好但页面已经开着** —— popup 会自动补注入内容脚本，不用刷新。`chrome://` 之类的内部页面注入不了。

## 已知限制

- Canvas Classic Quiz 支持原生单选/多选、独立 `.question_text` 题干，以及标签仅为大小写单字母、完整选项写在题干中的格式。空按钮在扫描中明确标记，模型仅接收有文字的候选，并保留原始 DOM 点击位置。无法确定按钮与题干的对应关系时显示「缺失」，整页有未正常作答的题目时停止提交。结果页可通过「扫描」查看并提示只读。附件验证范围是 Classic Quiz，Canvas New Quizzes 的嵌入页面尚未验证。
- Canvas Classic 的单输入数字题（`numerical_question` / `calculated_question`）也可扫描。可编辑页面用独立数值协议求解，填写后触发 input/change 并校验输入限制；仅高亮模式不写入。结果页的禁用输入只供扫描，题干不会混入已提交答案或反馈。多个输入暂标记缺失。题型依据 [Canvas 官方类型定义](https://github.com/instructure/canvas-lms/blob/master/app/helpers/quizzes_helper.rb)；新增数字题 DOM 测试按截图构建，尚未用第19题的完整实际 HTML 复测。

- v1.11.0支持题干和选项中的图片、原生Canvas图表及基本内联SVG。只在求解该题时编码；图片以PNG/base64连同文字，通过Chat Completions的`image_url`内容发送给用户配置的接口，细节级别为high。实现格式依据[OpenAI Docs视觉输入说明](https://developers.openai.com/api/docs/guides/images-vision)。必须选用支持视觉的模型和接口；原有「测试连接」只验证文字接口，不保证视觉能力。图片涉及额外图像输入用量。图片属于题目数据，里面的文字不改变答题协议。
- 每题最多8张图，本地编码最长边1800px，编码总量上限12MiB；下载单图上限8MiB。v1.12.0优先读取页面已载入图片；HTTP图片未加载或canvas不可读时立即从页面同源登录环境获取字节（8秒超时），不先等decode超时；页面CORS失败才交给后台（15秒超时）。API Key始终只用于模型请求。图片并行编码，相同资源的并发读取与编码复用；最多保留8份、合计16MiB的资源编码缓存。同一答题请求在内容脚本内合并。首次Alt+Shift+W后最多预取紧邻的下一道图片题，可能提前发生一次图文API用量，但不点击；有答案缓存时复用缓存，不会对整页提前请求。懒加载选源不改变题目hash；顺序完成记录绑定具体控件，重复内容的多道题不会被跳过。读取失败、无法转换、超限或接口拒绝图像时明确报错，不丢图继续作答。不会截图或发送整页、头像、导航和评分反馈。CSS背景图、跨域污染的canvas、复杂带外部资源的SVG、视频和拖拽配对尚不支持；模型对低清晰度图表或精确数值仍可能判断错误。
- Canvas Classic的`.matching_question`原生select按行提取完整题干、行标签和真实选项value。截图第7题的a/b/c/d./e.均保留，`[ Choose ]`不参与作答。使用实际附件11道题提取的DOM及原图测试，其中第7题展开成5个子项，总计15个可作答项。支持仅高亮、自动填写、全部成功后提交及Alt+Shift+W逐行选择和末尾核对；禁用行只读，行标签缺失或选项值重复时不自动填写。
- 题干抽取是启发式的。排版特别的站点可能混入无关文字（模型通常还是能答对，但会多花点 token）。
- 自定义组件如果读不出选中状态（没有 `aria-checked`、没有状态类名），提交前的校验只能默认点击生效了。
- 单字符选项（比如选项就是 `3`、`4`）不会从题干里被减掉，题干会带上它们 —— 这是刻意的，否则会把题干里的数字也抹掉。

## 测试

`test/` 下有二十二套自测，用浏览器直接打开 HTML；四套后台测试和一套原生GET/POST导航测试用 Node 运行，全绿为通过。全部使用模拟模型回复，不会发送真实API请求，也不代表真实模型答题准确率：

- `detector-test.html` —— 检测器的 15 条断言（含 Sage Vantage 的真实 True/False 结构、干扰项排除和题干清洁度）
- `flow-test.html` —— 一页一题的完整流程，7 条断言。内置假的 quiz 引擎（禁用的提交按钮、对错反馈中间页、网络延迟）和假的 `chrome` API，不需要 API Key，不发任何网络请求
- `sage-flow-test.html` —— 附件页面的交互回归，13 条断言。验证 `aria-labelledby` 题干、隐藏 radio、`btn-disabled` 解锁、提交按钮点击和无超时推进
- `reload-resume-test.html` —— Submit / Next 每次都销毁并重建页面，验证已答 hash 落盘、反馈页自动 Next、刷新后续跑和最终会话清理
- `background-session-test.js` —— 12 条断言，验证标签页会话存取、顶层页面跨 URL 恢复、答题 iframe 归属、无关 iframe 隔离、关闭标签页清理及 auto/highlight 会话类型保存和隔离。
- `activity-chain-test.html` —— 验证底部 `Next: Knowledge Check`、章节活动入口和新题之间的连续推进，并确保不误点导航栏同名链接
- `canvas-test.html` —— 21 条断言，验证附件17道题的只读扫描、68个完整选项、长题干在面板中的完整显示、模型请求与第10–17题扫描内容一致、可编辑测试副本的批量选中、Canvas 多选题和 Submit Quiz、结果页停止。`canvas-fixture.html` 只保存附件中的题目和选项 DOM，提取脚本是 `extract-canvas-fixture.py`。
- `canvas-review-test.html` —— 19 条断言，验证 Review Questions 附件16题的大小写映射、跨行文字、夹杂空按钮的原始点击位置、第4/5题明确报告源内容缺失，以及整页未答完时不会提交。`canvas-review-fixture.html` 保存该附件的题目 DOM。
- `canvas-numeric-test.html` —— 23 条断言。按第19题截图构建标准 Canvas 数字输入 DOM，验证只读扫描、题号与题干编号区分、反馈排除、数值填写及事件、0和负小数、无效回复拒绝、输入限制、多输入停止、提交后结束。
- `background-numeric-test.js` —— 15 条断言。验证数字题独立提示和JSON协议、数值解析、无效回复拒绝、数字答案缓存和原选择题协议。
